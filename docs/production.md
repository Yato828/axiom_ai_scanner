# Memorphia: запуск токенов и публичная эксплуатация

Пользователь может загрузить своё изображение или перенести результат из Mixer
Studio, заполнить название, тикер, описание и ссылки, подключить Phantom либо
Solflare и выпустить токен через Pump.fun в **основной сети Solana**. Покупка
токенов при создании не выполняется. Комиссии и rent оплачивает кошелёк создателя.

## Локальная разработка

Нужны Python 3.12 и Node.js 22+. В корне проекта:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
npm ci
npm run build
cp .env.example .env
python memorphia_dashboard.py web --host 127.0.0.1 --port 8080
```

Сайт: `http://127.0.0.1:8080/#launch`. Без Redis используются ограниченное
хранилище в памяти, один общий сканер и два фоновых обработчика изображений.
Состояние такого режима сбрасывается при перезапуске. Он предназначен для
локальной разработки в одном процессе.

## Что настроить для настоящего выпуска

Значения задаются в окружении сервера или локальном `.env`; ключи не добавляются
в браузерную сборку и репозиторий.

Настройки проекта используют префикс `MEMORPHIA_`. При обновлении существующей
установки перенесите настройки web и worker на имена из `.env.example` и
перезапустите оба сервиса вместе. Очередь Redis и данные браузера используют
пространство имён `memorphia`; завершите активные задания и проверьте отправленные
транзакции перед переключением.

| Переменная | Назначение |
| --- | --- |
| `SOLANA_RPC_URL` | HTTPS RPC основной сети с подходящими лимитами; адрес с ключом остаётся на сервере |
| `PINATA_JWT` | Загрузка изображения и JSON метаданных в public IPFS через Pinata |
| `MEMORPHIA_LAUNCH_ENABLED=1` | Разрешить создание токенов; `0` быстро отключает новые запуски |
| `WAVESPEED_API_KEY` / `WAVESPEED_API_KEYS` | Генерация изображений; в production достаточно задать worker |

Изображение и метаданные выпуска становятся публичными в IPFS. Загрузка файлов
в хранилище предшествует подписи транзакции; отказ от подписи не удаляет уже
загруженные публичные файлы.

Вход в кошелёк подтверждается одноразовым сообщением с адресом сайта, адресом
кошелька, nonce и сроком 5 минут. Сервер проверяет Ed25519-подпись. Сессия живёт
24 часа и хранится в `HttpOnly`, `SameSite=Strict` cookie (`Secure` на HTTPS).
Подключение кошелька и выпуск токена — отдельные подтверждения.

Транзакция создаётся в браузере из фиксированной инструкции `create_v2` по
[официальному интерфейсу Pump.fun](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/COIN_CREATION.md).
Её байты, порядок счетов и права проверены по эталону официального SDK 4.1.0
в `tests/fixtures/pump-create-v2.json`. Поддержан обычный SOL-pair; mayhem,
cashback, holder rewards и покупка при старте отключены. Seed нового mint
генерируется в браузере и не отправляется серверу. Ключ кошелька остаётся в
расширении или приложении кошелька.

Перед подписью проверяется genesis основной сети, выполняется симуляция и
оцениваются расходы с учётом rent. «Maximum launch cost» ограничивает оценку
перед подписью, а не задаёт отдельный лимит списания в смарт-контракте. Окончательные
параметры пользователь видит в кошельке. Через 60 секунд review нужно повторить.
Успех отображается только после `confirmed` или `finalized` без ошибки.

Подписанная транзакция сохраняется на устройстве до отправки RPC. При тайм-ауте
доступна проверка прежней подписи; новый mint автоматически не создаётся.
Сохранение на устройстве должно быть доступно. Нельзя гарантировать защиту от
дубликатов после очистки данных браузера или при одновременной работе с разных
устройств: перед повторным запуском нужно проверить кошелёк и историю Solana.

## Production

Используются три компонента:

```text
HTTPS / reverse proxy → Gunicorn web instances → shared Redis
                                            ↗
                           persistent worker
                      (market feed + image queue)
```

На web и worker задайте одинаковый `REDIS_URL` и `MEMORPHIA_ENV=production`.
Web дополнительно требует `MEMORPHIA_PUBLIC_ORIGIN=https://ваш-домен` без завершающего
пути. Без Redis production не стартует. Web и worker должны использовать одну
версию кода и конфигурацию фильтров рынка.

```sh
# Web; TLS завершает доверенный reverse proxy
gunicorn memorphia_scanner.web_wsgi:app --bind 0.0.0.0:8080 --workers 2 --threads 4 --timeout 90 --max-requests 2000 --max-requests-jitter 200

# Отдельный процесс с доступом к тому же Redis
python -m memorphia_scanner.worker
```

`Dockerfile` собирает интерфейс отдельно, устанавливает версии из lock-файла и
запускает Python без root. `docker compose up --build` поднимает локальную связку
web + worker + Redis. Перед этим нужен `.env`. Для публичной установки задайте
production и HTTPS origin, расположите web за TLS-прокси; Redis не публикуйте
в интернет. Для соединения через публичную сеть используйте авторизацию и TLS
(`rediss://`). Хранилищу требуется политика `noeviction` и персистентность; при
переполнении сервис вернёт контролируемую ошибку, а не потеряет сессии из-за LRU.

`render.yaml` описывает web, worker и Key Value на **платных тарифах**. Эти ресурсы
здесь не развёрнуты. Для существующего Render-сервиса новые секреты нужно
добавить вручную в настройках. Worker публикует в Redis доступность генератора
без API-ключей; web читает эту информацию. Vercel обслуживает только HTTP;
worker необходимо запустить на другом постоянном хостинге с тем же Redis.

Состояние сессий, nonce, лимитов, кеша и заданий общее для всех web instances.
Добавление экземпляров web не умножает запросы к рынку. Число обработчиков
генерации увеличивается отдельно; при нескольких worker-сервисах их параллелизм
суммируется. Redis следует выделить только этому приложению.

`MEMORPHIA_TRUST_PROXY=1` включается **только** за прокси, который заменяет
`X-Forwarded-For` и не позволяет клиенту обратиться к origin в обход. По умолчанию
клиентские forwarding-заголовки не используются. При другом устройстве proxy
нужно изменить извлечение IP перед включением этого режима. В `vercel.json`
доверие включено для [заголовка, перезаписываемого Vercel](https://vercel.com/docs/headers/request-headers).

## Быстродействие и ограничения

- Вся лента использует один snapshot, обновляемый worker раз в 45 секунд. Холодный
  кеш возвращает `202` для короткого опроса. При сбое данные сохраняются до 30
  минут и помечаются устаревшими. Один refresh защищён общей блокировкой.
- Сканирование обращается к провайдеру не более чем четырьмя параллельными
  запросами; отдельные поиски картинок для каждого токена удалены из пути скана.
- Генерация возвращает идентификатор задания сразу; результат запрашивается
  отдельно и доступен только кошельку владельца. Один idempotency key не создаёт
  повторное задание. При смерти worker платное задание автоматически не
  повторяется: спустя 15 минут UI сообщает о неопределённом результате. Необходимо
  проверить провайдера перед повторным запросом.
- Очередь ограничена 16 заданиями, по умолчанию работают 2 обработчика. Лимиты:
  3 генерации на кошелёк за 5 минут, 10 за сутки, 5 на IP за 5 минут и суммарно
  100 в час. Общий предел меняется через `MEMORPHIA_GENERATION_HOURLY_LIMIT`.
- API также ограничивает входы, записи и RPC. При насыщении возвращаются `429`
  или `503` с `Retry-After`. Защита не заменяет фильтрацию volumetric DDoS на edge.
- Общий размер запроса до 4,4 MB, исходное изображение до 3 MB и 16 мегапикселей.
  Изображения проверяются декодером, уменьшаются, очищаются от EXIF. При чтении
  URL разрешён публичный HTTPS с проверкой DNS и каждого редиректа; соединение
  привязывается к проверенному IP.
- CSP запрещает inline-скрипты, framing и внешние скрипты. SVG-файлы не принимаются
  как artwork запуска. Сборка локальна; кошелёк не загружается из стороннего CDN.
- Первоначальные модули запуска занимают примерно 14 KB gzip; модуль Solana
  около 83 KB gzip загружается только при review. Статика имеет ETag и кеш;
  API сессий, RPC, заданий и пользовательских файлов не кешируется публично.

Локальная проверка: 80 запросов к уже загруженной ленте, параллелизм 20,
80 ответов HTTP 200, p95 около 28 ms. Это проверка текущей машины, а не оценка
числа пользователей на production. Перед открытием большого трафика нужны
нагрузочная проверка целевого хостинга и наблюдение за памятью Redis, очередью,
ошибками RPC, расходами генератора и задержкой обновления ленты. Частота сжатия и
лимиты внешних провайдеров также влияют на итоговую скорость.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
npm test
npm run build
# После запуска локального сайта; используется установленный Google Chrome
npm run test:e2e
npm audit
```

Браузерные проверки используют тестовый кошелёк и подменённые RPC/IPFS/генератор;
настоящие деньги не расходуются. Реальный выпуск в mainnet и работа с production
RPC, Pinata и WaveSpeed требуют настроенного окружения и отдельной проверки
создателем кошелька. Docker-сборка требует запущенного Docker Engine.

Откат запуска: `MEMORPHIA_LAUNCH_ENABLED=0` блокирует подготовку новых metadata.
Уже подписанные/отправленные транзакции этот флаг отменить не может. При откате
кода сохраните Redis и проверяйте находящиеся в обработке транзакции до
повторного выпуска.
